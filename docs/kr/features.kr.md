# OpenNHP 기능 목록
{: .fs-9 }

OpenNHP는 네트워크 리소스를 보호하기 위해 강력한 보안성, 뛰어난 성능, 확장성을 제공합니다.
{: .fs-6 .fw-300 }


---

- **취약점 위험 완화:** TCP/IP 프로토콜의 개방성은 "기본적으로 신뢰하는" 연결 모델로 이어져, 누구든 서비스를 제공하는 서버 포트에 연결을 맺을 수 있게 합니다. 공격자는 이러한 개방성을 악용해 서버의 취약점을 노립니다. NHP 프로토콜은 서버 측에서 기본적으로 "전면 거부" 규칙을 강제해 인가된 호스트만 연결을 맺을 수 있도록 함으로써 제로 트러스트 원칙인 "절대 신뢰하지 말고, 항상 검증하라"를 구현합니다. 이를 통해 취약점 악용, 특히 제로데이 공격을 효과적으로 완화합니다.
- **피싱 공격 완화:** DNS 하이재킹은 인터넷 보안에 심각한 위협이며, 피싱, 민감 정보 탈취, 악성코드 유포 등 악의적인 목적으로 악용됩니다. NHP 프로토콜은 암호화된 DNS 해석 서비스 역할을 수행해 이 문제를 완화할 수 있습니다. 클라이언트 측의 NHP-Agent가 보호 대상 리소스의 식별자(예: 도메인 이름)를 담아 컨트롤러 구성 요소인 NHP-Server에 노크 요청을 보내면, NHP-Agent 인증이 성공한 경우에만 NHP-Server가 보호 대상 리소스의 IP 주소와 포트 번호를 반환합니다. NHP 통신은 암호화되어 있고 상호 검증되므로 DNS 하이재킹의 위험이 효과적으로 완화됩니다.
- **DDoS 공격 완화:** 앞서 설명한 것처럼, 클라이언트는 인증 없이는 보호 대상 리소스의 IP 주소와 포트 번호를 얻을 수 없습니다. 보호 대상 리소스가 여러 위치에 분산되어 있는 경우, NHP 서버는 클라이언트마다 서로 다른 IP 주소를 반환할 수 있어 DDoS 공격을 실행하기가 훨씬 어렵고 비용도 많이 들게 만듭니다.
- **공격 귀속(Attack attribution):** TCP/IP 프로토콜의 연결 모델은 IP 기반입니다. NHP를 사용하면 연결 모델이 신원(ID) 기반으로 바뀝니다. 연결을 시작하는 주체의 신원은 연결이 수립되기 전에 반드시 인증되어야 하므로, 공격의 식별과 추적이 훨씬 쉬워집니다.
- **기본 거부 접근 제어**: 모든 리소스는 기본적으로 숨겨져 있으며, 인증과 인가를 거친 후에만 접근할 수 있습니다.
- **신원 및 디바이스 기반 인증**: 승인된 디바이스를 사용하는 알려진 사용자만 접근할 수 있도록 보장합니다.
- **암호화된 DNS 해석**: DNS 하이재킹 및 이와 연관된 피싱 공격을 방지합니다.
- **DDoS 완화**: 분산된 인프라 설계로 분산 서비스 거부(DDoS) 공격을 방어하는 데 도움이 됩니다.
- **확장 가능한 아키텍처**: 구성 요소가 분리되어 있어 유연한 배포와 확장이 가능합니다.
- **IAM 통합**: 기존에 사용 중인 신원 및 접근 관리(IAM) 시스템과 함께 동작합니다.
- **유연한 배포**: 클라이언트-게이트웨이, 클라이언트-서버 등 다양한 모델을 지원합니다.
- **강력한 암호화**: ECC, Noise Protocol, IBC 등 최신 알고리즘을 활용해 강력한 보안을 제공합니다.
- 기본적으로 "전면 거부" 규칙을 강제해 취약점 악용을 완화합니다
- 암호화된 DNS 해석을 통해 피싱 공격을 방지합니다
- 인프라를 숨겨 DDoS 공격을 방어합니다
- 신원 기반 연결을 통해 공격 귀속을 가능하게 합니다
- 보호 대상 리소스 전체에 대한 기본 거부 접근 제어
- 네트워크 접근 전 신원 및 디바이스 기반 인증
- DNS 하이재킹을 방지하는 암호화된 DNS 해석
- DDoS 공격을 완화하는 분산 인프라
- 구성 요소가 분리된 확장 가능한 아키텍처
- 기존 신원 및 접근 관리 시스템과의 통합
- 다양한 배포 모델 지원(클라이언트-게이트웨이, 클라이언트-서버 등)
- ECC, Noise Protocol, IBC 등 최신 알고리즘을 사용한 암호학적 보안
